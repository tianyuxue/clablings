# Clablings 内容写作规范（Content Style Guide）

> 日期：2026-10-31（中文优先版）
> 适用：`clab-exercises` 的 `concept.md`、练习 `README.md` 与 YAML 人类文案
> 相关设计：`clab-exercises/docs/superpowers/specs/2026-10-31-chinese-first-content-design.md`

## 1. 目标

题库只维护中文内容，按中文技术写作习惯独立组织；不再维护英文摘要或双语对照。每一章都要回答三件事：**为什么需要它**、**它如何工作**、**怎么配置与验证**。

## 2. 中文主稿

### 2.1 推荐结构

按技术博客的节奏写，不按产品手册的目录写：

1. **先看现象**：用一个具体场景开场，先讲“出了什么事”，不要先甩定义。
2. **问题在哪**：把现象拆成可验证的判断，用设问往前推（“那再加一台行不行？”）。
3. **几个绕不开的术语**：定义放在场景之后；每个术语一句人话 + 一个例子。
4. **机制**：只讲和本章实验相关的判断逻辑，多用“你收到一帧，会怎么处理”这种视角。
5. **动手配一下 / 抓包看什么**：命令 + 预期现象，照着做就能复现。
6. **几个常见坑**：直接对应实验里的故障和断言。

标题可以带问句或冒号，例如“交换机到底怎么判断一帧属于哪个 VLAN？”，不必像手册一样
只写“工作机制”。

### 2.2 语言要求

- 语气像技术博客：可以讲故事、设问、对比，允许“你/我们”，但不要网络梗和语气词堆砌。
- 段落短，2–4 句一段；一句话只讲一个判断。
- 用主动语态；避免“进行 / 实现 / 用于 / 属于 / 处于 / 具备”这类公文式动词。
- 避免欧化长句、连续定语、破折号插叙和过多的“的”。
- 可以口语，但不要为了口语牺牲技术准确性；命令、编号、节点名必须精确。
- 避免直译词：
  - `knob` → “配置项 / 隔离机制”，不写“旋钮”
  - `on the wire` → “链路上 / 报文中”，不写“同一条线上”
  - `noisy testbed` → “高广播流量的测试平台”，不写“吵闹的实验台”
  - `silent failure` → “悄悄丢掉 / 很难发现”，不写“静默失败”
  - `put a bare frame into a VLAN` → “把裸帧分到 VLAN”
- 术语纪律：任何术语首次出现前必须在“术语”中定义；不要在中英文之间随意切换。

**手册体 → 技术博客体**

| 太像手册 | 更像博客 |
|---|---|
| 该端口仅属于单个 VLAN | 这个口只属于一个 VLAN |
| 用于为无标签帧打上默认归属标识 | 用来给不带标签的帧指定默认 VLAN |
| 对端无法区分该帧属于哪个 VLAN | 对端分不清这帧是哪个 VLAN 的 |
| 一旦配置不一致，流量将跨 VLAN 串扰 | 两端配得不一样，流量就会跑到别的 VLAN 里 |
| 交换机对广播帧的默认行为是全端口泛洪 | 交换机碰到广播帧，默认就是往所有端口泛洪 |

### 2.3 技术内容

- 命令、代码块、链接、拓扑节点名、VLAN/AS/接口编号必须与实验事实一致。
- 代码注释可以本地化；命令本身不能改。
- Common questions 必须覆盖实验注入的故障和断言点。
- 配置步骤要能直接复制执行，并说明预期观察结果。

## 3. 历史说明

旧版本曾保留英文摘要；该约定已由纯中文内容结构取代。

## 3. 英文摘要

- 保留中文稿中的全部可执行命令、链接和关键技术结论。
- 可以合并段落、减少小节、压缩解释；目标长度约为中文的 40%–60%。
- 不要求标题数量、段落数、句子数与中文一致。
- 练习 README 的英文摘要保留：任务目标、故障点、修复步骤、验证方式。
- YAML 英文字段保持简洁、准确，避免机翻式长句。

## 4. 阅读切片规范（只用免费来源）

字段（`reading.<lang>.yaml`）：

```yaml
- title: <文档全名>
  section: <精确小节标题>
  kind: required | optional
  url: <可直达该小节的锚点链接>
  intro: {en: ..., zh: ...}
  question: {en: ..., zh: ...}
```

硬规则：

- 只用免费、可直达的来源：RFC（rfc-editor.org）、Linux 内核文档
  （docs.kernel.org，带 `#anchor`）、项目官方文档、man7.org。
- `url` 必须带锚点；`section` 文本与来源标题一致。
- 每章 1–3 个切片；每个切片只服务一个具体问题；`intro` 必须点明与本实验的关系。
- 禁止只给首页、整本 man page、没有 `section` 或空泛的导读。

## 5. 反例

- ❌ `url: https://standards.ieee.org/standard/802_1Q-2022.html`（付费 + 首页）
- ❌ `section: LACP`（太宽泛）
- ❌ 中文出现“旋钮”“同一条线上”“静默失败”等直译词
- ❌ 为了和英文段落对齐而保留生硬的破折号和长定语
- ❌ 为了“结构一致”而删掉中文里必要的例子或排障说明

## 6. 落地检查

- [ ] 中文按场景 → 术语 → 机制 → 配置 → 排障的顺序讲清楚
- [ ] 术语先定义后使用，首次出现有英文名
- [ ] 没有直译词、欧化长句和破折号插叙
- [ ] 命令、代码块、链接与实验事实一致
- [ ] 英文摘要覆盖命令和关键结论，篇幅明显短于中文
- [ ] `clablings lint` 通过
- [ ] `clablings read <chapter> --lang zh` 渲染正常
